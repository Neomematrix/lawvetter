# AI Profile Enrichment: implementation and staging handoff

This branch extends the existing audit foundation and draft PR #2. **Not production-ready or deployed.** No production database, credentials, account settings, or deployment were used. All database writes during verification used in-memory SQLite fixtures.

## Repository inspection

LawVetter uses Vinext/React on Cloudflare Workers, D1 SQLite with Drizzle migrations, and R2 `PROFILE_PHOTOS`. `.openai/hosting.json` declares existing storage; `build/sites-vite-plugin.ts` packages migrations. Owner authentication uses the existing hashed admin session cookie and `CLAIM_ADMIN_EMAIL`, not client accounts or caller-supplied platform email headers. Admin routes retain the existing protected layout.

`attorneys` contains imported professional fields and source URLs. `attorney_profiles` contains optional website, practice areas, photo key and ownership. IDs may have state prefixes; identity checks use name, state, license number and official URL together. Firms are derived from `attorneys.company`, not a separate firm directory table. Existing logos include owner overrides and on-demand website discovery; existing banners have no persistent model. The committed Florida import has 120 owner-supplied PDF records, often missing admission dates, law schools and counties. No live attorney records were inspected.

## Implemented

- `/admin/enrichment`: owner dashboard, scan/missing/correction/image/approval metrics, state/entity/type/status filters, last/next scan, current/proposed text, evidence URL/retrieval/excerpt, image previews, approve/reject/defer, individually selected verified missing-text bulk approval, rollback, scan history and research exceptions. Results are bounded to 100 proposals; bulk selection is capped at 25.
- Eight enrichment tables for scan runs, jobs, receipts, immutable evidence, immutable proposal snapshots, decision audits, firm assets and image variants. Drizzle migration `0020_past_nick_fury.sql` includes custom transactional publication/rollback triggers.
- Approval triggers atomically recheck identity, current field value, evidence freshness, image rights/staging and claimed-profile protection. They only update allowlisted attorney professional/profile fields or firm banner assets. Reviews, user accounts, claims, biographies and unrelated records are never publication targets. A stale bulk item rolls back the entire selected batch. Rollback refuses newer edits or ownership changes. Original image files remain intact.
- Florida adapter with exact name/license/state verification, official HTTPS URL allowlist, labeled dt/dd or table extraction, excerpts and content hashes. Unknown layouts, access challenges, ambiguous identities, conflicting values and unsupported dates never become invented facts. Bar-listed firm/practice statements are attributed as self-reported. Georgia has no enabled adapter yet; the state-adapter registry is the extension point.
- At most 25 incomplete, unclaimed Florida profiles per scan; receipts skip unchanged snapshots for 30 days. Durable job attempts, backoff, scan leases, one active scan index and per-minute pacing. Interrupted scans resume from stored jobs. Manual scan creation and owner-controlled processing are available. Source research performs at most two requests per profile (robots and record), without credentials, redirects or CAPTCHA bypasses. Only bounded downloads are accepted.
- Worker scheduled handler gates new nightly scans to the Eastern midnight hour using `Intl` and an idempotent local-date key. A per-minute worker trigger also resumes jobs outside that hour. EST/EDT and both 2026 DST transition dates are tested. Trigger delivery can be delayed by the provider; this is not a hard real-time guarantee.
- Research receives a restricted database facade: no live-record/decision writes or client-account/review reads. This is a code capability boundary. D1 itself has no per-table database roles; stronger isolation requires a separately deployed narrow storage service. No database/API secrets are sent to GitHub Actions.
- Image triage checks dimensions, sampled Laplacian sharpness and portrait aspect ratio on bounded JPEG/RGB PNG input. These are heuristics, not face recognition, crop correctness or compression-artifact guarantees. Owner supplies/attests an authorized original or reuses an existing R2 portrait and provides identity/design and usage-rights evidence. Cloudflare IMAGES stages non-generative contain resizing and modest sharpening. Originals, desktop/mobile variants and source hashes are retained. No face restoration, generative detail, relighting, logo redesign or decorative effects.
- Portrait variants are 800×1000 and 400×500; banner variants 1600×533 and 800×267. Whole-image contain fit preserves proportions. Approved portraits use the existing photo endpoint, mobile variants via srcset; approved banners use a responsive picture element. Pending previews require the owner session and are not publicly readable.

## Configuration and remaining scope

1. Review and apply migration 0020 **to an isolated staging D1 only**, after existing migrations. The generated journal/snapshot are included. Preserve the custom triggers and partial indexes in future migrations. Do not apply it to production as part of this task.
2. Bind staging `DB`, `PROFILE_PHOTOS` and Cloudflare `IMAGES`; reuse a staging owner account configured through `CLAIM_ADMIN_EMAIL`. No LLM key is required: facts are extracted deterministically. IMAGES must be available for actual transforms. The binding output was mocked in unit tests, not validated against a paid staging service.
3. Review `worker/enrichment-schedule.example.jsonc`. Merge its minute trigger into the deployment provider's staging worker config. The Sites source metadata does not configure Cron Triggers by itself. Leave both `ENRICHMENT_SCHEDULE_ENABLED` and `ENRICHMENT_SOURCE_ACCESS` disabled until the staging source-access review succeeds; set each to `enabled` deliberately afterward. Manual scans also require source access before processing. No trigger or runtime variables were changed remotely.
4. Florida Bar returned **HTTP 403 / Cloudflare “you have been blocked” on 2026-10-31**. No bypass was attempted. Obtain a permitted API/export or approved accessible HTML and add real captured parser fixtures before enabling live research. The current parser is verified only against synthetic labeled markup, not the site's blocked current HTML. An existing working link does not establish server-side access.
5. Independent firm-site corroboration, automated better-original discovery, unrestricted logo retrieval, automatic rights verification and a Georgia adapter remain unimplemented. Image originals are owner-uploaded/reused with evidence. No automated face matching, aesthetic crop verification, JPEG artifact classification or denoising is claimed. Those require separately validated source/image integrations. Conflicting text requires individual review (defer then explicitly approve only after resolving the evidence); bulk excludes conflicts and image proposals.
6. Validate real authorized portraits/logos visually and exercise the actual IMAGES service in staging. Synthetic previews and transform-option tests cannot establish facial/design fidelity on real people or logos. Bound CPU/memory processing on the selected paid Worker plan and load-test representative staging data before production. Existing approved banners are not automatically reclassified for quality; imported firms initially have no approved banner asset.
7. No production performance/load claim is made. Queries and batches are bounded and worker processing is asynchronous; tests do not replace load testing. The image library is worker-side, not added to public client bundles. Failed staging uploads may leave private unreferenced objects; retain for diagnostics and add an explicit retention policy before scale-up. Audit/evidence retention must preserve rollback provenance.

## Verification

- Existing baseline tests passed before changes. Final results are recorded in `docs/enrichment-verification.md`.
- Twenty-five clearly synthetic incomplete Florida records in `tests/fixtures/enrichment/profiles.json`; no real attorney is assigned synthetic professional facts. Migration tests apply the complete migration chain to fresh SQLite databases.
- Matching/URL ambiguity, missing facts, invalid dates, conflicting fields, 403/redirect handling, robots and response-size limits; resumability, maximum batch size, receipt skipping, overlap prevention and retry exhaustion.
- Real owner API authorization: anonymous/spoofed identity denied, owner cookie accepted, missing/foreign Origin denied, source access disabled by default, private image access protected.
- Atomic bulk approval, immutable evidence/audits, ownership and identity changes, stale evidence, unrelated-table attempts, compare-and-set rollback and retained originals.
- Image dimensions/blur heuristics, same original input for each transform, contain/mild-sharpening-only options, staged variants and photo approval/rollback. Real output fidelity remains a staging requirement.
